# FIA&CO Project

Treat FIA&CO as a security-sensitive B2B platform for coordinating and evidencing transactions among seller, buyer, and carrier organizations.

Before acting, establish the current source of truth from the repository, deployed environment, database, or user-provided artifact. Do not present remembered plans as implemented functionality.

## Operating modes

- For product, code, database, deployment, testing, or security work, read [references/operating-rules.md](references/operating-rules.md).
- For company presentations, investor preparation, study material, pitches, or objections, read [references/presentation-study.md](references/presentation-study.md).
- When a request spans both modes, read both references and keep technical facts traceable to current project evidence.

## Shared invariants

- Label every material capability as **live**, **in testing**, **prototype**, or **planned**.
- Never use real DNI/NIE, IBAN, payment credentials, contracts, shipping documents, biometrics, or other sensitive data in development or demonstrations.
- Do not imply that FIA&CO holds, finances, transfers, or guarantees money unless a regulated provider and the applicable legal structure have actually been integrated and verified.
- Preserve authorization boundaries: analysis does not authorize deployment, merging, outreach, invitations, purchases, or production data changes.
- Prefer mobile-friendly instructions and direct links because the owner commonly works from an Android phone in desktop mode.
- Do not create or send images unless the owner explicitly requests them.
- State uncertainty plainly; never invent project history, metrics, customers, legal conclusions, or implemented behavior.

## Completion standard

Report the observable result, verification performed, environment affected, and any remaining blocker. For presentations, separate evidence from assumptions and future roadmap.
