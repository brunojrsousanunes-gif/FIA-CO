# PLR-1/2/5 — Operaciones, métricas y experiencia

Estado: preparación técnica de candidato a piloto. No inicia una prueba real.

## Operación completa
Crear operación -> definir condiciones -> aceptar -> registrar hitos/evidencias -> gestionar incidencia si existe -> cierre documentado.

Registrar identificador de operación, tiempos, resultado, incidencias y necesidad de asistencia, evitando datos personales innecesarios.

## Objetivos de validación
Como referencia inicial para una futura prueba controlada: 20–30 usuarios, 30–50 operaciones completas y cero pérdida o corrupción de expedientes. Son objetivos de evaluación, no garantías ni requisitos contractuales.

## Métricas
- tasa de finalización;
- tiempo de ciclo;
- abandono;
- incidencias por operación;
- asistencia requerida;
- móvil frente a escritorio;
- uso y aceptación de recomendaciones Premium.

Objetivo de producto tras estabilización: al menos 90% de operaciones completables sin asistencia directa. El resultado deberá medirse durante la prueba, no presumirse antes.

## UX
Validar móvil y escritorio, onboarding, comprensión de estados, accesibilidad básica, prevención de doble acción, errores recuperables y flujo de incidencias.
